Implementació de la primera història d'usuari
Heu d'implementar la primera història d'usuari de l'Sprint 1, vinculada a l'èpica "Submissions":

AS a logged user I WANT to view all the submissions SO THAT I want to know what is going on
A continuació, més instruccions.

Aquesta història d'usuari implica només una pàgina: news, que hauria de tenir una aparença el més semblant possible a l'original de HN. La pàgina news, que també és l'arrel de l'aplicació, mostra submissions de diferents usuaris, ordenades de més rellevants a menys. HN calcula aquesta rellevància amb un algorisme propi; de moment, per simplificar, ordeneu-les per points.
Es tracta de de fer una web app clàssica, és a dir, tot el contingut, tant estàtic com dinàmic, es genera al servidor web. Per tant, no s'ha d'utilitzar JavaScript per a res.
Les submissions són creades per un usuari, que és el seu creador. Per tant, de moment tenim dues classes d'entitats (models): User i Submission. Les submissions poden ser de tipus "url" o "ask", segons com es faci el submit; ara només cal contemplar les de tipus "url" que són la majòria a la pàgina news i que corresponen a enllaços a pàgines externes. Abans d'implementar la història d'usuar, us recomanem fer l'scaffolding d'aquests dos models, tal com vau fer a la tasca #2 del waslab04, per tal de generar automàticament les corresponents Vistes, Controladors i Models que després podreu modificar per adaptar-los als vostres requisits.
Ompliu la BD amb submissions i users, per tal de poder tenir un llistat inicial d'almenys 10 submissions amb diferents títols, users, enllaços, temps de creació i points.
Intenteu també fer un primer desplegament a Render, Heroku o algun altre PaaS.

Implementació de la segona història d'usuari
Heu d'implementar la segona història d'usuari de l'Sprint 1, vinculada a l'èpica "Submissions":

AS a logged user I WANT to add a new submission SO THAT I want to make my own contribution
Aquesta història d'usuari implica quatre pàgines: submit, newest, news i ask. Han de tenir una aparença el més semblant possible a les originals de HN.

Per crear una submission des de la pàgina submit (a HN la podeu veure a https://news.ycombinator.com/submit després de fer el registre/login). Les submissions són de dos tipus, depenent de si s'omple o no el camp url:
Si s'omple el camp url amb un URI vàlid: la submission es considera de tipus "url".
Si es deixa el camp url buit: la submission es considera de tipus "ask".
El camp title és sempre obligatori, mentre que el camp text és opcional. Independenment del tipus, després de crear una submission amb èxit, es mostra la pàgina newest, amb la nova submission al principi de tot.
La pàgina newest mostra les submissions ordenades per temps, de més recents a menys. També s'hi pot accedir des de l'enllaç new de la barra de menú superior.
La pàgina news ja la teniu implementada. La pàgina ask és com la news, però només mostra les submissions de tipus ask i s'hi accedeix des de l'enllaç ask de la barra de menú superior.
